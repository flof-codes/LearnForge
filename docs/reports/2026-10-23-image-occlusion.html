Image occlusion cards

A figure with labels covered, one card per covered label. Stored in Anki's own format, so Anki imports, Lecture Scribe uploads and a later .apkg export all speak the same note. Parts 1–5 of the brief are built; nothing is merged or deployed.

What is done

1 · Note type + renderer done

Built-in occlusion ("Image Occlusion"), kind cloze, fields Occlusion, Image, Header, Back Extra, Comments. {{cloze:Occlusion}} renders each shape as a positioned <div> with Anki's classes and data attributes. Pure CSS percentages: scales at any width, no canvas. Rect, ellipse, polygon, text labels, rotation, oi=1. Tap to zoom 2×, "Toggle masks" on the back.

2 · Anki import done

Anki IO notes land on the built-in type (fields by name, else Anki's stock order) with their media; cards are studyable, Anki's own suspension kept. A boot migration moves notes an older import left as unsupported onto the built-in type, keeps schedules, deletes the copied type. A re-import does the same.

3 · POST /notes done

note_type: "occlusion" works with the lfa_ app token (route was already allowed). Validation: picture present, known shapes, fractions not pixels, at least one asked shape. source_ref idempotency as for every note.

4 · Tutor done

Occlusion cards are served as type: "card", never sent to the question writer (/tutor/prepare and /tutor/next). Study cards carry noteTypeKey. The chat tutor's skill gets a short rule not to spoil the unmasked picture.

5 · Mask editor done

On the card editor of an occlusion note: drag to draw a rectangle, drag to move, corner handle resizes, number field groups masks into cN, delete, "hide all, guess one", raw-text fallback. Full-bleed at phone width.

Decisions and limits

  • Kind stays cloze; the built-in key tells occlusion apart (noteTypeKey). No third kind rippling through the code.
  • No canvas, no Anki JS. Anki's markup plus inline percentages, so the card also draws where scripts do not run. The script only zooms and toggles masks.
  • Anki 23.10 beta pixel coordinates (values > 1) are not drawn correctly; current Anki writes fractions. POST /notes refuses them.
  • Built-in CSS is copied per account. A later CSS fix to the occlusion type does not reach accounts that already have the type; the figures session's upgrade step in ensureBuiltinTypes is the place to add a CSS refresh for uncustomized built-ins.
  • .apkg export does not exist yet (release 3b). The fields are Anki's, so the exporter only has to write Anki's stock IO note type (originalStockKind 6) around them.
  • Chat review (MCP) attaches the unmasked picture. The skill now tells Claude not to spoil it, but a masked render for chat is a follow-up.

Ideas beyond the brief

  • Masked image for chat review (my pick): composite the masks onto the picture with sharp in card-media.ts for occlusion fronts, so Claude in chat can show exactly the asked region.
  • Lecture Scribe auto-masks: text detection on a figure slide (Apple Vision on the Mac) gives a box per label, which is a ready occlusion note to check in this editor.
  • "New occlusion note" button in the web app (upload picture → editor). Today notes come from Anki, Scribe or the API; the editor edits existing ones.
