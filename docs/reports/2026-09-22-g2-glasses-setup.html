LearnForge on G2

Goal: review LearnForge cards as tiny single- or multiple-choice questions on the G2 glasses, at every Bloom level, operated only with the R1 ring. Claude compiles each card into a question that fits the display ahead of time, so the ring loop never waits. The start screen picks the session mode, MCQ or voice; this report designs the MCQ path. It shows every view, marks when data leaves the glasses, and draws where Claude sits between authoring a card and answering it.

Where Claude sits: three moments

Compile output is validated server-side against the character caps below and stored in micro_mcq_cache. When a card is edited, its compiled questions are dropped and rebuilt on the next compile run. Cards that cannot be compressed, for example formula-heavy ones, come back with skip and stay in chat.

Every view, and what it sends

Pair first launch

LearnForge Connect this device at learnforge.eu/glasses Code K7F4 2Q Waiting for confirmation...

No ring input. Code expires after 10 min. Token then lives in the SDK's own storage on the phone.

sendsPOST /glasses/pair/start with the hash of a device-generated secret, then POST /glasses/pair/poll every 2 s (status only)

Home every open

Due 12 New 3 Streak 7 d Accuracy 7 d 86% Bloom 0-1: 14 2-3: 6 4-5: 2 > MCQ single MCQ multi Speech (later) tap = start · hold = menu

Same numbers as the web app's study summary, and the only screen with stats. The cursor picks one of three session modes. Speech is shown but disabled until it has its own design.

sendsGET /glasses/summary

Preparing rare

Preparing 5 questions... Cards edited since the last compile are rebuilt first. hold = menu

Shown only when the cache is cold. Normally the batch returns in well under a second.

sendsGET /glasses/next?mode=&limit=5

Question · single swipe + tap

Which quantity is conserved in an elastic collision only? > A Kinetic energy B Momentum C Mass D Charge ? I don't know tap = answer

Question only, no header. Swipe moves the cursor and wraps. Tap on a letter answers at once. One text container, updated in place.

no network cursor moves are local

Question · multi toggle, confirm

Which are vector quantities? Select all that apply. [x] A Velocity > [ ] B Speed [x] C Force [ ] D Energy -> Confirm ? I don't know

Tap toggles the row. The Confirm row submits. Options and both action rows share the same cursor, so the ring needs nothing new.

no network until Confirm

Result · correct tap

OK A Kinetic energy Inelastic collisions turn kinetic energy into heat and deformation. Momentum is conserved in both. tap = next

Explanation is the compiled one-liner, max 3 lines. Next question is already on the phone, so tap is instant.

sendsPOST /glasses/reviews with the ticket and the letter; the server grades

Result · wrong or partial tap

X You chose B Momentum Right: A Kinetic energy Momentum is conserved in every collision. Only elastic ones keep kinetic energy. tap = next

Multi-select shows which letters were right and missed. Rating follows the tutor rules: partial credit possible.

sendsPOST /glasses/reviews with the ticket and the letters; partial credit from the review service

I don't know explanation

Answer: A Kinetic energy Elastic: kinetic energy and momentum both conserved. Inelastic: only momentum. Think billiard balls vs. clay. tap = next

Same layout as a wrong answer, but the full explanation fills the screen. Counts as "Again" so the card comes back soon.

sendsPOST /glasses/reviews with dont_know: true; recorded as rating 1

Menu and Done hold · end

tap, then hold: Skip card Change topic Home Close app ----------------------------------- Done. 12 reviewed, 9 right. tap = home double tap = exit

Menu is the system contextual menu, up to 10 items. Skip sends nothing, the card stays due. Double tap on the root page opens the mandatory exit dialog.

no network except Home, which refetches the summary

Reviews are queued in bridge storage and retried, so a dropped Bluetooth or Wi-Fi link never loses an answer. Every 5 answers the app fetches the next batch. The glyph set is fixed and unknown characters are dropped silently, so markers stay ASCII (OK, X, [x]) until the font-measurement skill confirms ✓ and ✗ exist.

Data flow of one session

CallAuthWhenPayload worth knowing
POST /glasses/pair/start · POST /glasses/pair/pollnone, rate limitedFirst launchThe glasses generate a 32-byte secret and send only its SHA-256. Poll returns pending or claimed, never a token. The admin claims the code with POST /glasses/claim in Settings → Glasses.
GET /glasses/summaryglasses tokenEvery open, and Home from the menuDue, new, streak, 7-day accuracy, Bloom distribution. Nothing else.
GET /glasses/nextglasses tokenStart, then when 2 questions are leftDue cards with a fresh compiled row at their current level, one study-session ticket each. mode=single serves one-correct rows, mode=multi all rows. exclude keeps cards with an unsent review out.
POST /glasses/reviewsglasses tokenEvery answer, Confirm, or I don't knowTicket plus letters, or dont_know. The review service grades: single hit = 4, multi by hits minus wrong picks, I don't know = 1. Replaying a ticket returns the first result, so the offline queue can retry.

Setup, in order

  1. Unlock Developer Mode

    Pair G2 and R1 in the Even Realities app, update firmware. Sign in at hub.evenrealities.com, which flips the account to developer. Force-quit and reopen the phone app; the Even Hub tab now shows "Scan QR".

    Florian · phone and glasses in hand

  2. Install the tooling

    npm install -g @evenrealities/evenhub-cli @evenrealities/evenhub-simulator

    Node 20 LTS or 22+. Optional: the everything-evenhub Claude Code plugin marketplace adds 12 Even Hub skills for building.

    Claude · after your OK

  3. Scaffold the glasses/ workspace

    npx degit even-realities/evenhub-templates/minimal glasses

    Add "glasses" to the root workspaces. The template ships Vite, TypeScript and the SDK.

    Claude

  4. Write glasses/app.json

    {
  "package_id": "eu.learnforge.glasses",
  "name": "LearnForge",
  "version": "0.1.0",
  "edition": "202601",
  "min_sdk_version": "0.0.14",
  "entrypoint": "index.html",
  "permissions": [
    { "name": "network", "desc": "Fetch questions and save reviews",
      "whitelist": ["https://learnforge.eu", "http://192.168.x.x:3333"] }
  ],
  "supported_languages": ["en", "de"]
}

    One full origin per entry, no wildcards. The http entry is dev only. Name max 20 characters, no "Even" in it.

    Claude · you supply the LAN IP and the production API origin

  5. Backend: compile service, pairing, next batch

    Migration for glasses_tokens and micro_mcq_cache. Core service compileMicroMcq with the JSON schema above and server-side cap validation. Routes in api/src/routes/glasses.ts. Runner A uses @anthropic-ai/sdk with ANTHROPIC_API_KEY in the API container. Runner B is an MCP tool compile_glasses_questions that accepts the same JSON and writes the cache.

    Claude · after decisions 1 to 3

  6. Glasses app: nine views, one reducer

    src/main.ts awaits waitForEvenAppBridge(), creates one full-screen text container with isEventCapture: 1, and routes onEvenHubEvent into a state machine: pair, home, preparing, question, result, done. Token and the review queue live in bridge.setLocalStorage. Handle FOREGROUND_EXIT and FOREGROUND_ENTER for the 2-minute idle check.

    Claude

  7. Web-ui: Connect glasses page

    Settings → "Connect glasses" with one code input and a revoke button. DE and EN strings.

    Claude

  8. Run it on the glasses

    npm run dev -w glasses
evenhub qr --url "http://<laptop-lan-ip>:5173"

    Scan from the Even Hub tab. Same Wi-Fi, port 5173 open. The simulator sends clicks as sysEvent while hardware uses textEvent, so the reducer accepts both.

    Florian scans · Claude drives the simulator

  9. Package for daily use

    npm run build -w glasses
evenhub pack glasses/app.json glasses/dist -o learnforge-glasses.ehpk

    Upload in the Even Hub portal as a Beta build. Beta installs without review and survives phone lock, which QR sideload does not.

    Florian uploads · Claude builds

Decisions

Decided 2026-09-22: 1 = compile by Claude Code only, no API-key route, feature admin-only. Revised the same day: the api runs the bundled Claude Code on the server when the app opens (Florian signs it in there), so no manual step is needed. 2 to 5 = A. Session mode (MCQ single, MCQ multi, Speech) is chosen on the Home screen; only the two MCQ modes are built now.

1 Who compiles the questions decided 2026-09-22: B only, admin only

SituationA Max subscription may not be used from the LearnForge server, neither yours nor a user's. An API key on the server is fine. A user's own Claude Code calling the LearnForge MCP is fine.
A · RecommendedBoth runners. Server API key as default for every user, about 1 cent per card. Plus the MCP tool so you fill your own cache from Claude Code on Max.
BServer API key only. Simpler, and your cards cost you cents too.

2 How the glasses log in

SituationPassword login only today. No keyboard on the glasses.
A · RecommendedGlasses show a 6-character code, you type it once in web-ui, the app polls until claimed. Zero ring typing.

A · RecommendedI don't know = 1, always. Multi-select keeps the tutor's precision-and-recall ladder 4 / 3 / 2 / 1.
BI don't know = 2 when the card is new, to avoid punishing first contact. Everything else as A.

Open questions

  • Which API origin do the glasses call in production? Default: the same host as the web app, one https origin in the whitelist.
  • Does a glasses session pick a topic, or take all due? Default: all due; "Change topic" in the menu lists top-level topics.
  • Single or multi by default? Default: Claude chooses per card; the tutor rules default to multi, and binary or definition cards become single.
  • Cards with formulas or images? Default: Claude may return skip; those cards stay in chat and are not counted as due on the glasses.
  • What does "Start voice" do on the glasses? Default: out of scope here. Needs its own design around the mic, an ASR path and text-only feedback. The row is shown so the start screen is final.
  • Do we render ✓ and ✗? Default: ASCII until the font-measurement skill confirms the glyphs.
  • Glasses token lifetime? Default: 90 days, revocable from the Connect glasses page.
  • Cache invalidation when the tutor rules change? Default: yes, the cache key includes a prompt version string.
