The Credential Line

Question: may LearnForge compile glasses questions with a Claude Max subscription, ours or a user's, and is "a wrapper around Claude Code" enough to make that legal? This report reads Anthropic's current rules, looks at how T3 Code stays on the right side of them, and maps the allowed paths for LearnForge.

The rule in one picture

Anthropic draws the line on two questions: whose credential is it, and whose software makes the request to Anthropic.

What Anthropic actually says

OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications.Claude Code docs, Legal and compliance, "Authentication and credential use"
Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens.same page. This rules out a user's Max on the LearnForge server and a Claude login button in LearnForge.
Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication through Claude Console or a supported cloud provider.same page. The Agent SDK is named explicitly, which matters for how T3 Code is built.
Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code.same page. This sentence is what makes T3 Code and a LearnForge companion possible.

How T3 Code does it

Mechanism

What it isOpen-source GUI for coding agents by Theo Browne's team. A Node WebSocket server on the user's machine wraps provider CLIs, with web, desktop and mobile clients on top.
Claude pathThe Claude provider adapter launches the locally installed, unmodified claude binary through the official Agent SDK. T3 discovers the binary, checks it, and spawns it as a child process.
CredentialsNone. The user runs claude login themselves. T3 ships no model credits, never sees the OAuth token, never talks to Anthropic's API directly. Its docs: bring your own provider accounts.
Why it passesCredential holder is the user. Requesting software is Anthropic's own binary. T3 is a remote control for a Claude Code the user already runs, not a harness of its own.

One tension remains in the text: the same page says Agent SDK developers "should use API key authentication", while T3 uses the SDK with the user's subscription. The unmodified-binary sentence is what covers it, and Anthropic has not moved against T3 since. Treat this as tolerated and documented, not as a guarantee.

So is "a wrapper around Claude Code" legal?

Not any wrapper. Three conditions have to hold at the same time, and the request has to leave from the user's machine, not from a LearnForge server holding their token.

1 · Unmodified binaryInstall and run Claude Code as Anthropic publishes it. Do not remove, disable or restrict any built-in login method.
2 · The user's own loginEach user signs in to Claude Code themselves through Anthropic's flow, with their own subscription or key. Their usage is billed to them.
3 · No intermediationLearnForge never pays for, resells or routes their Claude usage, and never collects, stores or forwards their tokens. Running Claude Code inside a product also means accepting the Commercial Terms.

Naming: you may say in plain text that LearnForge "runs Claude Code". You may not put Claude or Anthropic in a feature name or logo.

Decisions

1 Which compile runners to build

SituationThe glasses need compiled questions before a session. Your Max cannot fill the cache from the server, but it can from your Claude Code.
A · RecommendedBuild A and B together. A is the default for everyone; B is one MCP tool plus a skill so you compile on Max from Claude Code.
BBuild A only. Your own compiles cost cents on the API key. Simplest, no MCP change.

2 Companion app

SituationPath C is allowed but is the most code and the most fragile, as T3's 401 issue shows.
A · RecommendedNo companion. Document path B for subscription users who want to avoid API-key cost.
BBuild a companion later, after the glasses flow is stable and there are users asking for it.

Open questions

  • Does a scheduled Claude Code routine that compiles 50 cards nightly count as "ordinary use"? Default: yes when you set it up in your own Claude Code for your own cards. Keep batches small and on demand rather than a nightly sweep.
  • Should LearnForge accept the Commercial Terms explicitly now? Default: already implied by using a Console API key for path A. No extra step.
  • Ask Anthropic sales for confirmation? Default: not for A and B. Only if path C is ever built.
